# TUR-012 — Shrinking Windows from the installer to make room for TUR (issue 64, step 2)

```text
TUR DEVELOPMENT REPORT

Task ID:          TUR-012 (issue #64 step 2)
Subsystem:        Installer medium (installer/iso: engine, text installer,
                  medium packages), graphical installer, tests/iso, workflow iso
Build ID:         see the runs of the head commit of pull request 116
Source revision:  the head of feat/beside-windows-shrink (pull request PR_NUMBER)

SUMMARY
- What changed: both installers offer "Make room by shrinking Windows" on
  a disk that holds Windows where there is not enough free space (or more
  is wanted): the person picks the room for TUR (from 25 GiB up to what
  Windows can give while keeping 16 GiB free for itself), chooses the
  default system, reads that a backup is strongly recommended, and types
  "SHRINK" and the end of the serial number. The engine then shrinks the
  Windows partition (ntfs-shrink.sh: refusals first — BitLocker, hibernated
  or Fast Startup, marked for a check, too full — then ntfsresize
  --no-action, the resize, the partition entry, a comparison of the table)
  and installs beside Windows into the space freed (ADR-0029). ntfsprogs is
  on the medium (not in the image).
- Why it changed: issue 64, step 2; the owner decided on 14 November 2026
  that it is to be offered.

FILES
- Added: installer/iso/rootfs/usr/lib/tur-installer/ntfs-shrink.sh,
  tests/iso/ntfs-shrink-test.py, desktop/apps/tur-installer/fixtures/
  same-disk/install-shrink*.jsonl, this report.
- Modified: installer/iso/Containerfile (ntfsprogs), engine.sh
  (shrink_look, run_shrink), tur-install (option 3, size, confirmation),
  tur-install-engine (--mode shrink --tur-size); the wizard (option, size
  field, confirmation, stage, words, tests); tests/iso/install.py
  (scenario shrink), windows-disk.py (--shrunk), beside-report.py;
  .github/workflows/iso.yml (job ntfs-shrink; a shrink run in job beside).
- Removed: nothing.

BUILD
- Command: none; the job installs Ubuntu's ntfs-3g on the runner.
- Result / Warnings: see "CI runs".

TESTS
- Unit tests: none.
- Integration tests: tests/iso/ntfs-shrink-test.py (iso, job ntfs-shrink);
  the text installer shrinks a 55 GiB Windows partition holding little and
  installs TUR into 26 GiB (iso, job beside): the partition shrunk in place,
  every file of its root unchanged, the other partitions byte-identical.
  The wizard's QML tests: the option, the size limits, the confirmation,
  a failure while shrinking.
- Boot tests: TUR's first start after the shrink. Windows' boot from the
  shrunk volume: NOT RUN (no Windows).
- Hardware tests: NOT RUN.
- Performance tests: the shrink's duration is recorded.

DIAGNOSTICS
- Log paths: the CI artifact tur-ntfs-shrink (ntfs-shrink.json, summary.md).
- Relevant error IDs: TUR-INSTALL-SHRINK-001 to -008 (in the library's header).

RECOVERY
- Rollback procedure: revert the pull request; the installers then offer
  only the free space beside Windows and erasing.
- Recovery tested: only as measured interruptions, below.

KNOWN LIMITATIONS
- **Real-Windows safety: NOT RUN.** Every volume was made by mkfs.ntfs
  (ntfs-3g); the screens say so.
  Windows' own volumes (a system volume with its pagefile, $LogFile in use,
  compressed and sparse files, shadow copies) were not tried.
- ntfsresize has no journal: a power cut while it moves clusters can damage
  the volume. Windows' own Shrink Volume (step 1) stays the recommended way.

NEXT SAFE ACTION
- Try it on a real Windows only after a backup; a test with a real Windows
  image in CI needs a licence that allows it (owner decision).
```
