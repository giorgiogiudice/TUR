# windiff fix queue: patches to Wine

**Not under TUR's licence.** These are patches to Wine and are under Wine's
licence, the **GNU Lesser General Public License, version 2.1 or later**
(Wine's `COPYING.LIB`; a verbatim copy is in
[`third-party/wine-patches/COPYING.LIB`](../../../../third-party/wine-patches/COPYING.LIB)).
They follow the conventions of the existing queue in
[`third-party/wine-patches`](../../../../third-party/wine-patches): one
`git format-patch` file per fix with a licence note above it, applied with
`git apply` in the order of [`series`](series).

| | |
|---|---|
| Against | Wine master `9f8c4ae4` (the `wine-11.22` tag), pinned in [`../ci/wine-pin.sh`](../ci/wine-pin.sh) |
| Also checked against | `wine-11.20` (`7298a818`), the version Fedora 45 ships: `ci/wine-master.sh` reports whether each patch applies |
| Applied and built by | [`../ci/wine-master.sh`](../ci/wine-master.sh), in CI only; the whole of Wine is built once and kept, a patch rebuilds what it touches |
| Verified by | the windiff check that found the difference (it must match Windows afterwards and no other check may change), and a test added to Wine's own conformance tests, which the workflow runs under the patched Wine and on real Windows |
| Shipped | never: this queue exists to measure the fix loop |

Each patch was written from what the check programs observed on Windows
through the documented API, and from Wine's own source. No Microsoft source
code, leaked code or disassembly was read.

The author line is a placeholder. Wine takes contributions under a real
name, and its maintainers have said they do not accept code generated by a
language model (see the report, `docs/reports/exp-windiff-1.md`, for exactly
what they say). These patches were written by one. They are evidence of
what a fix looks like and what it costs, not merge requests.

The queue lives beside the experiment while it is a spike, so that changing
it starts only the spike's workflow; `third-party/wine-patches` is where a
kept queue belongs.
